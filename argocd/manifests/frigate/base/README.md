# Frigate pilot compatibility ceiling

`0.18.0` is pinned to the standard amd64 image index digest, not the `-tensorrt` variant. The current Frigate 0.18 NVIDIA ONNX/TensorRT path is unsafe to assume on the cluster's Quadro P4000 (Pascal, compute capability 6.1): CUDA ONNX kernels may not include this architecture, and the installed NVIDIA driver is 535.309.01, below Frigate's documented CUDA 12 runtime minimum 545. The deployment therefore makes no GPU/runtimeClass claim and explicitly uses Frigate's bundled CPU TFLite detector as a one-camera pilot. It will be materially slower than hardware inference; observe detector latency/CPU and stop or provision a supported accelerator if it cannot sustain load.

The default image is compatible with standard CPU detection and permits the NVIDIA Video Codec SDK decoder preset if later explicitly validated, but this staged config does not enable it: driver compatibility and actual NVDEC operation are unverified. No model was downloaded. `/dev/shm` (256Mi) and `/tmp/cache` (1Gi) are memory-backed and count against the pod's 4Gi limit.

Before syncing, confirm `/volume1/surveillance/frigate` exists and is writable from the scheduled node; the NFS export itself was confirmed, but directory/write access was not tested. Confirm MQTT/Vault synchronization and certificate issuance after normal GitOps reconciliation. Ingress routes through the colocated oauth2-proxy sidecar to Frigate's authenticated port 8971; unauthenticated 5000 is absent from the Service and restricted to kubelet node probes by NetworkPolicy. The proxy validates Keycloak's dedicated frigate-admin client role, emits `frigate_roles`, and overwrites the Frigate identity and proxy-secret headers. Frigate defaults to viewer; only the explicitly assigned client-admin role maps to Frigate admin. TLS is requested through cert-manager's `letsencrypt-prod` issuer. See `rollback.md` for controlled, non-public recovery.

The exact selected image index digest was read from GHCR's authenticated anonymous token flow.
